<objective>
Add one explicit repo-origin clause to the `jobs.sync.if` gate in `.github/workflows/sync-branches.yml`
so the job provably cannot run off a fork's CI run, and update the explanatory comment to say why.

Purpose: closes SonarCloud `githubactions:S7631` (HIGH / VULNERABILITY, line 33 —
"Make sure that no untrusted code is executed from a fork"), flagged on the `workflow_run` trigger.
The existing `event == 'push'` clause already implies same-repo origin (a `push`-triggered CI run in
this repo's Actions namespace can only come from someone with write access), and the job never
executes checked-out code — it is pure git plumbing (`checkout`, `merge --ff-only`, `push`). This
clause is therefore acknowledged-redundant defense-in-depth: it is the most literal answer to the
rule's stated concern and makes the safety legible to human reviewers and static analysis alike.

| `workflow_run` payload → `jobs.sync.if` | GitHub-generated metadata (`conclusion`, `head_branch`, `event`, `head_repository`) is the only thing standing between a fork run and a privileged `git push` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-eq4-01 | Elevation of Privilege | `jobs.sync` `workflow_run` trigger with `contents: write` | mitigate | Add `head_repository.full_name == github.repository` to the `if` gate (Task 1) so the job is unreachable from any fork-originated CI run, on top of the existing `event == 'push'` clause |
| T-eq4-02 | Tampering | checked-out tree at `workflow_run.head_sha` | accept | Job never executes tree content — no build, no install, no script invocation. Only `git checkout` / `merge --ff-only` / `push`. Nothing in the tree is interpreted, so tampered content has no execution path |
| T-eq4-03 | Spoofing | `workflow_run.head_repository` value itself | accept | Field is GitHub-generated event metadata, not attacker-supplied input; GitHub Security Lab's own safe-pattern guidance treats `workflow_run` payload fields as trustworthy for gating |
