<objective>
Delete `.github/workflows/sonarcloud.yml`, the CI-based SonarCloud analysis workflow, so the repo relies solely on SonarCloud Automatic Analysis.

Purpose: SonarCloud's two analysis modes are mutually exclusive. Per SonarSource's own docs, "Automatic analysis is not intended to be used in conjunction with CI-based analysis... these CI-based analyses will fail and cause a failure in your build process." This project has Automatic Analysis active — the external `SonarCloud Code Analysis` check passes on every PR, sourced from SonarCloud directly with no CI involvement. Meanwhile `sonarcloud.yml` has run 71 times since 2025-12-15 and failed all 71. That is a 100% failure rate from day one, which rules out an expired token and confirms the documented mode conflict. The workflow is pure noise: it cannot succeed while Automatic Analysis stays on.

Output: One staged file deletion. No other file changes.
</objective>

<known_consequence>
Surfacing this rather than burying it — it is real, it is accepted, and it is **out of scope for this plan**:

`sonar-project.properties` lines 14 and 17 point at artifacts that **only the deleted workflow produced**:

- `sonar.go.coverage.reportPaths=.coverage/profile.out,.coverage/e2e.out`
- `sonar.go.golangci-lint.reportPaths=golangci-lint-report.xml`

After this deletion nothing generates those files, so both keys go inert and SonarCloud will stop receiving Go coverage and golangci-lint data. Those metrics on the Sonar dashboard will go stale or empty.

**Why this is acceptable:** neither metric was ever a merge gate. Coverage enforcement lives in `ci.yml`'s `Coverage Check` job (a required check, and the 79% floor from CLAUDE.md); lint enforcement lives in `ci.yml`'s `Lint` job (also required). Sonar was a read-only dashboard for both. Since the workflow failed 71/71 times, Sonar has in fact **never** received these reports — so nothing regresses; the config was already dead.

**Why we still leave the two lines in place:** the constraint for this task is a single-file deletion. SonarCloud ignores report paths whose files are absent, so the dead keys are harmless. Deleting them is a separate, optional cleanup the developer can choose later. Do NOT edit `sonar-project.properties` in this plan — its `sonar.exclusions` and `sonar.cpd.exclusions` values (tuned by quick tasks 260403-skg and 260405-ixt3) are live inputs to Automatic Analysis and must stay byte-identical.
</known_consequence>
